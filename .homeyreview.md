# Context for the review

- **What it is**: an unofficial app for Suprema BioStar 2, an on-premise access control server. It has no
  drivers or devices by design: BioStar 2 readers report events, and the app turns those into Flow triggers,
  conditions and two actions. All configuration lives in the app settings page.
- **Name and ID**: the name is the brand name only ("BioStar 2"), as guideline 1.1 asks. The app ID keeps its
  original `.community` suffix because an ID cannot change after the first publish. The store texts state that the
  app is not affiliated with or endorsed by Suprema Inc.; the icon is original artwork and the store photo is a
  free stock photo (Unsplash License).
- **Network**: local only. The user enters the BioStar 2 server URL; the app talks to that host alone over HTTPS
  (REST) and a WebSocket. No cloud service, no third-party endpoints, no Homey permissions.
- **Why the server URL is entered by hand**: BioStar 2 is a server application (Windows or Linux) at an address
  of the user's choosing, usually a host name with its own TLS certificate and often behind a reverse proxy.
  Suprema documents no network discovery (mDNS/SSDP) for it, so there is nothing for `ManagerDiscovery` to find.
  The settings page explains the field, and Test Connection checks the address and credentials.
- **TLS**: certificate verification is on by default. The user can switch it off in settings for a BioStar 2
  server with a self-signed certificate on their own LAN; this is the only place `rejectUnauthorized` can be false.
- **Credentials**: the BioStar 2 password is stored in Homey's app settings and never sent to the settings page;
  Test Connection only reuses it for the saved host and user.
- **Physical effect**: the *Open door* action releases a door through BioStar 2, exactly like the console's Open
  Door button, and needs the matching BioStar 2 permission. No other card controls hardware.
- **Storage**: the activity log is in memory by default. Only when the user enables "keep the log across
  restarts" is it written to `/userdata`, capped at about 256 KB and deleted when the option is turned off.
